# OpenViking

> 状态: 活跃 | 标签: agent, memory, context, 上游贡献 | 分类: agent-runtime/memory

## 定位

OpenViking 是字节跳动/火山引擎开源的面向 AI Agent 的上下文数据库，为团队在上游 Agent 基础设施层的关注项目。我们关注其在高性能向量检索、混合存储引擎、以及 Agent 记忆管理方面的设计思路，作为团队内部 Agent 记忆方案的参考和技术储备。当前标签为上游贡献。

## 项目介绍

OpenViking 是专为 AI Agent 场景设计的上下文数据库（Context DB），提供统一的长短期记忆存储与检索能力。它融合了向量数据库的高维检索、关系型数据库的结构化查询以及图数据库的关联遍历，使 Agent 能够在对话和工作流中高效访问历史上下文、工具调用记录和知识片段，支撑复杂 Agent 多轮交互与多步骤任务执行。

## 核心场景

- **Agent 长对话记忆管理**：在多轮对话中自动存储和检索历史上下文，解决 LLM 上下文窗口有限的问题，支持 Agent 在超长会话中保持连贯记忆。
- **多 Agent 协作共享记忆**：多个 Agent 之间共享工作记忆，支持任务分解、结果传递和历史上下文复用，提升多 Agent 协作效率。
- **工具调用结果缓存**：缓存 Agent 的工具调用结果（API 返回、文件读取、数据库查询等），避免重复调用，降低延迟和成本。
- **个性化知识索引**：根据用户偏好和历史行为构建个性化知识索引，使 Agent 响应更贴合用户习惯和业务场景。

## 技术要点

- **混合存储引擎**：融合向量索引（ANN/IVF/HNSW）与结构化存储，在同一系统中同时支持语义检索和精确过滤查询，避免了 Agent 需要同时集成多个存储系统的复杂性。
- **上下文窗口管理**：内置智能上下文选择策略，根据相关性评分动态挑选最相关的记忆片段注入 LLM 提示，而非简单截断或全量载入。
- **分层记忆架构**：借鉴认知科学中的记忆模型，实现工作记忆（短期，存入当前会话上下文）、情节记忆（中期，存储完整交互历史）和语义记忆（长期，提炼的知识和模式）三层结构。
- **高并发低延迟检索**：针对 Agent 场景的实时检索需求优化，支持毫秒级向量检索延迟，满足 Agent 在推理循环中对记忆的频繁查询。
- **图关系关联**：支持在记忆片段之间建立图关系（来源引用、因果链、版本迭代等），使 Agent 能够追溯信息的来源和演进过程。
- **多租户与隔离**：支持按 Agent、用户、会话维度的数据隔离，保障不同租户之间的记忆安全性和独立性。

## 技术栈

- 语言：C++/Python
- 向量索引：HNSW、IVF、DiskANN 等
- 存储引擎：自研混合存储（向量 + 结构化的统一存储层）
- 接口：REST API、gRPC、Python SDK
- 部署：支持单机部署和分布式集群
