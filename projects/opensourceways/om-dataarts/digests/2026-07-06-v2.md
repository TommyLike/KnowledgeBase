## 关键特性变更

- **⚠️ 新增开发者仓库维度贡献统计** (#372, +743/-145): 新增 `contribute_user_repo_daily` 任务，按仓库维度统计开发者 D0/D1/D2 贡献及详情，创建 `dwm_{community}_contribute_user_repo` 表，支持 co-author 解析。这是本周最大变更，为开发者页面提供仓库级数据底座。

- **⚠️ 新增塔台贡献 ES→PG 同步链路** (#395, #396, #403): 新增 `blue_contribute_sync` 任务将塔台贡献数据从 Elasticsearch 同步到 PostgreSQL 的 `fact_all_blue_contribute` 表，支持全量和增量两种同步模式，复用 `whitebox_blue.yaml` 配置。补建索引解决贡献明细按 comment 筛选时卡顿的问题。

- **ttfhw_issue 问题采集多项增强** (#397, #399, #402, #407, #412, #413): 问题采集链路大幅改进：新增 `source`（数据来源）、`source_line`（链接 report.json 具体行）、`problem_type`（文档问题/过程问题分类）三个字段；ingest 阶段从拉取 335 份运行报告精简到 15 份代表性 final_reports；支持 gitcode 建 issue（token 从 service_platform_config 读取）；去掉冗余级别字段，body 表格拆分标题/正文分列写入；修复确认问题后重复创建 issue 的幂等缺陷（新增原子行认领+存在性检查+失败释放机制）。

- **论坛用户数据补全** (#409, +434/-17): 通过 VCS API 鉴权拉取远程 `company_rules.yaml`，自动填充论坛用户的 company 和 internal 字段，新增 name 字段到论坛用户表，统一 uuid 对齐。

- **oss-insight 预览修复** (#391, #393, #394): 预览链路三轮修复——改用 GitHub Contents API 取内容解决 raw_url 对私有仓库返回 404；预览内容改为取 PR 改动文件解决预览与 PR 实际内容不一致；新增 PR 预览同步到需求表（pr_url + preview_html）。
