## 一、定位

灵衢(UnifiedBus,UB)不是另一个互联协议,而是**面向 AI 时代数据中心的新型计算系统架构**。核心思想:把 CPU/NPU/GPU/内存/存储/Switch 等所有组件通过 UB 总线级互联,构建**逻辑上的一台计算机**——超节点(SuperPoD Reference Architecture)。

## 二、六大架构特征

### 1. 总线级互联

- **百 ns 级同步内存语义**访问时延,2-5μs 异步时延
- 组件间 **TB/s 级带宽**,比传统数据中心网络至少提升 10×
- 支持 64B-4KB 及变长单事务操作,基于 Flit 传输机制

### 2. 协议归一

- 单一协议栈统一 CPU/NPU/GPU/MEM/DPU/SSU/Switch 等**所有组件类型和距离**的互联
- 无协议转换开销,统一编程模型
- 四大事务类:内存(Memory)、消息(Message)、维护(Maintenance)、管理(Management)

### 3. 平等协同

- 超节点内所有组件**去中心化互访**,无需经过 CPU 中转
- 通过 Entity ID(EID)+UMMU(地址翻译和权限控制)+UBFM(Fabric 管理)实现
- 支持所有通信范围:节点内/柜内/超节点内/集群内

### 4. 全量池化

- **UB Partition** 支持多用户隔离(UPI=UB Partition ID)
- 资源授权后可被多方直接通过 MMIO/消息访问
- 互联资源(多通道/多端口)同样池化共享

### 5. 大规模组网

- 超节点从单节点**线性扩展到 8192 卡**(>90% 线性度),未来 15488 卡
- 通过 UBoE 构建**百万卡集群**,兼容以太组网
- 拓扑:Full Mesh / Clos / nD-Mesh / 2D-FullMesh + Clos 混合 / OCS 光交换

### 6. 高可用性

- **us 级**检错和容错,应用无感知
- 8192 卡超节点光互连 MTBF **>6000 小时**
- 分层可靠:链路层重传(LLR) → 物理降 Lane → 光模块 2+2 备份 → 多路径切换 + 端到端重传

## 三、灵衢协议栈(7 层)

```
功能层: Load/Store + URMA 编程接口
事务层: 内存/消息/维护/管理 四大事务
传输层: 带宽聚合、连接共享、端到端可靠传输
网络层: 大规模组网、动态路由、多路径均衡
链路层: 点对点流控+重传、Flit 传输
物理层: 单 Lane 118Gbps,线性直驱光
UMMU + UBFM: 全局地址翻译 + Fabric 管理
```

## 五、UB-Mesh 组网(NVIDIA 论文级引用)

arXiv:2503.20377 — UB-Mesh: A Hierarchically Localized nD-FullMesh Datacenter Network Architecture

核心思路:充分利用业务数据局部性,优先短程直连,减少交换机使用。2D-FullMesh 用于极致低时延(内存共享场景),2D-FullMesh+Clos 混合用于训练/推理(64→8192 卡线性扩展)。

## 六、灵衢软件配套

操作系统只需增加灵衢组件(UB OS Component),提供 4 个扩展:
- **Device Mgmt**:UB 设备热插拔和配置
- **Memory Mgmt**:跨节点内存借用和共享
- **Communication**:跨节点/跨设备通信和远程调用
- **Virtualization**:UB 设备直通虚拟机

## 七、与昇腾 950 的关系

灵衢是昇腾 950 芯片的互联协议(UB 2.0),昇腾 950 是第一个搭载 UB 2.0 的芯片产品。白皮书提到"已在 Atlas 900 A3 SuperPoD 等产品实践与验证",并将灵衢系列技术规范对业界开放(www.unifiedbus.com)。
